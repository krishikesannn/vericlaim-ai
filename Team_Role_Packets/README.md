# VeriClaim AI Team Role Packets

This folder contains eight learning packets. Each packet has a chapter-based study guide and copies of relevant source/docs. Large dataset and model artifacts remain in the canonical project to prevent conflicting copies.

## Team map

1. [Project Lead and Product Owner](01_project_lead_product_owner/STUDY_GUIDE.md) - Own the problem definition, scope, team coordination, customer value and the final evidence-based story.
2. [Data and Validation Engineer](02_data_validation_engineer/STUDY_GUIDE.md) - Own dataset understanding, data-quality checks, perceptual grouping, leakage analysis and repeatable validation evidence.
3. [Deep-Learning Engineer](03_deep_learning_engineer/STUDY_GUIDE.md) - Own image preprocessing, EfficientNetV2B0 transfer learning, CNN fraud heads, augmentation experiments and standalone CNN evaluation.
4. [ML and Ensemble Engineer](04_ml_ensemble_engineer/STUDY_GUIDE.md) - Own Extra Trees, MLP, archive similarity, leakage-safe stacking, calibration, thresholding and performance comparison.
5. [Backend and Model Integration Engineer](05_backend_integration_engineer/STUDY_GUIDE.md) - Own the reliable connection between uploads, saved model artifacts, prediction API responses, application state and local deployment.
6. [Frontend and UX Engineer](06_frontend_uiux_engineer/STUDY_GUIDE.md) - Own clear, accessible, trustworthy claim and investigation experiences, including Model Lab and model-comparison presentation.
7. [QA, MLOps and Model Governance Engineer](07_qa_mlops_governance_engineer/STUDY_GUIDE.md) - Own test strategy, reproducibility, release gates, monitoring, model card quality, auditability and responsible-use controls.
8. [Presentation, Documentation and Business Analyst](08_presentation_documentation_business_analyst/STUDY_GUIDE.md) - Own the evidence-backed presentation, requirements traceability, documentation quality, demo narrative and business-value explanation.

## Shared handoff rule

Every role must record artifact version, data/validation assumptions, tests run, metrics observed, known limitations and the next owner. No role should change the active model or website without a reproducible record.
